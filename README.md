# Retail A/B Test Analysis Pipeline

End-to-end data pipeline that ingests raw session data, runs a full statistical A/B test analysis (significance, SRM validation, segment breakdown, financial impact), and orchestrates it all with Apache Airflow — built on Docker.

**Stack:** Apache Airflow · Apache Superset · PostgreSQL · Docker · Python (pandas, scipy, numpy)

---

## 📌 TL;DR

A retail website (UK) tested changing its background color from **white (A)** to **black (B)**. The analysis found a statistically significant **+8.67 percentage point lift in conversion** (5.40% → 14.07%, p = 6.57e-25), consistent across devices and regions, with no sample ratio mismatch. **Recommendation: roll out.**

> ⚠️ Note: the underlying dataset is synthetic and the effect size is unusually large by design — see [Data Source](#-data-source) below. The methodology, not the magnitude, is the point of this project.

---

## 🎯 Hypothesis

Changing the site background from white to black increases user conversion rate.

## 📊 Results

### Primary metrics

| Metric | Group A (White) | Group B (Black) | Change | p-value | Significant? |
|---|---|---|---|---|---|
| Conversion | 5.40% | 14.07% | +8.67 pp | 6.57e-25 | ✅ Yes |
| Time spent | 241.7 s | 243.3 s | +0.7% | 0.639 | ❌ No |
| Page views | 7.58 | 7.49 | −0.9% | 0.436 | ❌ No |

- Sample size: A = 2,519 · B = 2,481
- MDE (conversion): 1.79 pp
- Test: Welch's t-test (time spent, page views) · Chi-square (conversion)
- **Recommendation: ROLL_OUT**

### Sample Ratio Mismatch (SRM) check

Before trusting the result, the group split itself was validated — a skewed split can invalidate an otherwise "significant" test.

| Metric | Value |
|---|---|
| Group A / B | 2,519 / 2,481 |
| Observed ratio | 0.5038 |
| Chi-square | 0.2888 |
| p-value | 0.591 |
| SRM detected? | **No** ✅ |

### Segment analysis

The lift was checked for consistency across devices and regions, rather than trusting a single aggregate number.

**By device**

| Device | n (A) | n (B) | Conv. A | Conv. B | Lift (pp) | p-value |
|---|---|---|---|---|---|---|
| Mobile | 1,275 | 1,187 | 4.94% | 14.24% | +9.30 | ~0 |
| Desktop | 1,244 | 1,294 | 5.87% | 13.91% | +8.04 | ~0 |

**By location**

| Location | n (A) | n (B) | Conv. A | Conv. B | Lift (pp) | p-value |
|---|---|---|---|---|---|---|
| Wales | 629 | 602 | 4.77% | 15.12% | +10.35 | ~0 |
| Scotland | 670 | 611 | 4.93% | 15.06% | +10.13 | ~0 |
| England | 606 | 640 | 6.93% | 14.69% | +7.76 | 1.7e-05 |
| Northern Ireland | 614 | 628 | 5.05% | 11.46% | +6.42 | 6.4e-05 |

**Findings:**
- The effect is stronger on mobile (+9.30 pp) than desktop (+8.04 pp).
- Wales and Scotland show the largest lift (+10.35, +10.13 pp).
- Northern Ireland shows the smallest lift (+6.42 pp) but remains statistically significant.
- The effect direction is consistent across every segment — no segment contradicts the overall result.

## 🏗️ Architecture

```
Kaggle CSV → data/data.csv
                ↓
    Docker volume mount (./data:/data/company)
                ↓
    PostgreSQL: user_sessions (5,000 rows)
                ↓
        ┌───────┴───────┐
        ↓               ↓
   Airflow DAG      Superset
   (scheduled           (dashboards,
   analysis)            in progress)
        ↓
   ab_test_history / financial_impact / segment_analysis
```

**Services**

| Container | Image | Port | Purpose |
|---|---|---|---|
| `postgres_data` | postgres:16 | 5433:5432 | Session data + analysis results |
| `airflow` | custom (`my-airflow:2.9.0`) | 8080:8080 | Orchestration + scheduler |
| `airflow_db` | postgres:16 | internal | Airflow metadata |
| `superset_app` | apache/superset:latest-dev | 8088:8088 | BI dashboards (in progress) |

A custom Airflow image (`Dockerfile.airflow`) is used because the base Airflow image blocks `pip install` as root, and the project needs pinned, ABI-compatible versions of `numpy`/`pandas`/`scipy`.

## 🛠️ Engineering notes

A few non-obvious issues surfaced while building this pipeline and are worth documenting, since they're easy to hit again:

- **Airflow base image blocks `pip install`.** Solved with a custom image (`Dockerfile.airflow`) pinning `numpy==1.26.4`, `pandas==2.1.4`, `scipy==1.11.4`, `psycopg2-binary==2.9.9` — versions chosen to avoid a `numpy.dtype size changed` ABI mismatch.
- **`-h` vs `-H` in Airflow 2.9.0.** `-h` resolves to `--help`, not `--hostname`. The webserver needs `-H 0.0.0.0`, or it silently prints help and exits.
- **DAGs not showing in the UI.** Usually means the scheduler isn't running — `airflow scheduler` and `airflow webserver` both need to run in the same container (`airflow scheduler & airflow webserver ...`).
- **Writing dicts into a `JSONB` column.** `str(results_dict)` produces single-quoted, invalid JSON. Use `json.dumps(results)` instead.
- **Connecting from inside a container.** Scripts running inside the `airflow` container must use `postgres_data:5432`, not `localhost:5433` — the latter only works from the host machine.
- **`COPY` failing on a fresh database.** The source CSV headers (`User ID`, `Group`, `Page Views`, ...) don't match the table's column names (`user_id`, `group_type`, `page_views`, ...), and `COPY ... CSV HEADER` only *skips* the header row — it does not map columns by name. Fixed by listing target columns explicitly and in CSV order:

  ```sql
  COPY user_sessions (user_id, group_type, page_views, time_spent, conversion, device, location)
  FROM '/data/company/data.csv'
  DELIMITER ','
  CSV HEADER;
  ```

  Verified reproducible from scratch: run against a clean database, all 5,000 rows loaded successfully (`COPY 5000`).

## 🚀 Setup

**Prerequisites:** Docker, Docker Compose, Git.

```bash
git clone https://github.com/koloskostya4-cyber/data-pipeline-project.git
cd data-pipeline-project

# 1. Build the custom Airflow image
docker build -f Dockerfile.airflow -t my-airflow:2.9.0 .

# 2. Start all services
docker-compose up -d

# 3. Load schema and data
docker exec -i postgres_data psql -U data_user -d my_dataset < scripts/sql_queries.sql

# 4. Initialize Superset
docker exec -it superset_app superset db upgrade
docker exec -it superset_app superset fab create-admin
docker exec -it superset_app superset init
```

**Access:**
- Airflow: http://localhost:8080 (admin/admin)
- Superset: http://localhost:8088 (admin/admin)
- PostgreSQL: `localhost:5433`, db `my_dataset`, user `data_user`

### Running the analysis manually

```bash
# Core A/B test + SRM check
docker exec -it airflow python /opt/airflow/scripts/ab_test_calculator.py

# Financial impact scenarios
docker exec -it airflow python /opt/airflow/scripts/financial_impact.py

# Segment breakdown (device, location)
docker exec -it airflow python /opt/airflow/scripts/segment_analysis.py
```

Or trigger the scheduled DAG directly:

```bash
docker exec -it airflow airflow dags unpause ab_test_analysis
docker exec -it airflow airflow dags trigger ab_test_analysis
```
